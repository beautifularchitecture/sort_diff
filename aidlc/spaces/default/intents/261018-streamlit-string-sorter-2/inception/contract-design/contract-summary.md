# Contract Summary

## Scope

Formal contracts across the workflow's boundaries, derived from the three-Unit DAG (U1 sorting-core → U2 playground-ui → U3 delivery-pipeline).

**External boundaries: none.** The requirements rule out external integrations and public APIs (NFR3.4, out of scope "external system integrations", "hosting beyond Streamlit Community Cloud"). The Streamlit page is an end-user surface, not a programmatic contract, so no external API specification is produced.

## Contracts

| # | Provider Unit | Consumer | Mechanism | Owner |
|---|---|---|---|---|
| 1 | U1 sorting-core | U2 playground-ui | synchronous in-process Python API | U1 |
| 2 | U2 playground-ui | U3 delivery-pipeline | build and run interface (entry script, commands, dependency declaration) | U2 |

## Contract 1 — sorting-core API (U1 → U2)

```yaml
contract: sorting-core-api
version: 1
provider: sorting-core
consumer: playground-ui
mechanism: in-process-call
types:
  SortInput:
    run_id: string          # generated by InputProcessor.normalize, one per run
    raw_entries: list[string]
    normalized_strings: list[string]
  AlgorithmResult:
    run_id: string
    algorithm: enum [bubble, selection, quick]
    sorted_strings: list[string]
    comparisons: integer    # >= 0, element comparisons (FR4.2)
    swaps: integer          # >= 0 (FR4.3)
  AccuracyCheck:
    run_id: string
    algorithm: enum [bubble, selection, quick]
    passed: boolean
operations:
  normalize:
    input:
      entries: list[string]   # typed lines and picked words, in that order
    output: SortInput
    rules:
      - split each entry on newline and comma
      - trim surrounding whitespace
      - drop empty tokens
      - lowercase ASCII capital letters A-Z only
      - non-ASCII characters pass through unchanged (decision D10)
      - duplicates are kept
  run_all:
    input:
      sort_input: SortInput
    output: list[AlgorithmResult]   # exactly three, in order [bubble, selection, quick]
    rules:
      - all three algorithms receive the same normalized_strings
      - empty normalized_strings returns three results with empty sorted_strings and zero counts
      - run_id is copied from sort_input into every result
  check:
    input:
      result: AlgorithmResult
      sort_input: SortInput
    output: AccuracyCheck
    rules:
      - passed is true only when result.sorted_strings equals sorted(sort_input.normalized_strings)
      - each algorithm is checked independently
errors:
  - code: TypeError
    when: entries is not a list of strings (caller defect)
  - code: ValueError
    when: result.run_id differs from sort_input.run_id (caller defect)
  - note: no other exceptions cross this boundary; in-process, so no timeout or retry behaviour applies
```

**Resolves the Domain Design review finding 3** (no component generated `run_id`): `InputProcessor.normalize` generates it and is the owner of `SortInput`.

## Contract 2 — app packaging interface (U2 → U3)

```yaml
contract: app-packaging-interface
version: 1
provider: playground-ui
consumer: delivery-pipeline
mechanism: build-and-run-interface
entrypoint: app.py            # Streamlit entry script at repository root
dependencies: requirements.txt  # declares streamlit; U2 owns this file
local_run: streamlit run app.py
test_command: pytest
lint_command: ruff check .
format_check_command: black --check .
```

Consumers (U3) invoke these commands exactly as written. The CI workflow does not reach into U2 source.

## Contract Ownership Rules

- **U1 owns contract 1.** Its signatures and types are changed only in the same squash-merged change that updates U2's call sites. U1 and U2 ship together from one repository, so a breaking change never exists on `main` on its own.
- **U2 owns contract 2.** Renaming `app.py`, changing a command, or changing the dependency file requires the same-change update to U3's workflow.
- **Additive changes are safe.** New optional fields on result types and new operations do not break existing callers.
- **No external consumers**, so no semantic versioning policy applies. The `version` field is recorded for traceability only.
